# 決定ログ

新しい決定は末尾に追記する。決定を覆す場合は元の行を消さず、新しい行で「D-xxx を変更」と書く。

| ID | 日付 | 決定 | 理由 |
|---|---|---|---|
| D-001 | 2026-09-16 | Health Connectの読み取り専用Viewerとして企画する | 同期後に「実際に何が入っているか」「どのアプリが書いたか」「長期でどう推移したか」を確認できるアプリがなかった |
| D-002 | 2026-09-24 | Android専用とし、iOSは対象外 | Health ConnectはAndroidの仕組みであり、iOS版の需要がない |
| D-003 | 2026-09-24 | Kotlin + Jetpack Composeで開発する（React Native / Flutterは不採用） | iOS不要でクロスプラットフォームの利点がない。大量レコードのJSブリッジ転送が重い。Health Connectの新APIへ即座に追従できる |
| D-004 | 2026-09-24 | minSdkは28を第一候補とする | SDKはAPI 26から使えるが、Health Connect自体が動くのはAndroid 9以上 |
| D-005 | 2026-09-24 | ホームの期間は今日／週／月／年をすべて必須。詳細は1YとALLを必須、3Y・5Yは検討 | 年単位・全期間で見られることが、このアプリを作る最大の動機 |
| D-006 | 2026-09-24 | 体重カードの比較は「前回比」 | 毎日測るとは限らないため、前日比より実態に合う |
| D-007 | 2026-09-24 | アプリ独自の重複判定はせず、Rawレコードは重複も含めてすべて表示する | 目的は「Health Connectに何が入っているか」を見ること。独自判定を公式の重複処理と誤認させるリスクもある |
| D-008 | 2026-09-24 | グラフの集計方法はデータ型・表示期間ごとに定義し、画面に明示する | Aggregate APIで取れる値はデータ型ごとに異なり、公式の重複処理もActivity / Sleepにしか効かない（外部レビューの指摘） |
| D-009 | 2026-09-24 | ソース別のレコード件数の仕様は性能検証後に確定する | 件数はAggregateで取れず、全件走査が必要なため（外部レビューの指摘） |
| D-010 | 2026-09-24 | AdMobを導入する。形式は画面下部のバナーのみ、パーソナライズ広告は許可（UMPに従う） | 収益化のため。全画面広告は「見る体験」を損なう。パーソナライズに使われるのは健康データではない |
| D-011 | 2026-09-24 | 「No cloud」「No network」は訴求せず、「健康データを外部送信しない」と表現する。健康データは広告・Analytics・ログに一切流さない | AdMobの導入で通信が発生するため。健康データの広告利用はGoogle Playのポリシーで禁止されている |
| D-012 | 2026-09-24 | 広告削除は非消費型の買い切り。MVPはクライアントのみで実装 | サーバーを持たない閲覧アプリで、広告削除だけのサブスクは割高に感じられる。改ざんされても損害が小さい |
| D-013 | 2026-09-24 | Room（ローカルDB）はPoCの結果を見て判断。Hiltは依存が増えてから導入 | 健康データをアプリ内に複製しない方がプライバシー方針と合う。PoC段階では過剰 |
| D-014 | 2026-09-24 | 公開リポジトリとし、ライセンスは付与しない（All rights reserved） | 開発の過程を公開したいが、第三者が同じアプリをストアに出すことは認めない |
| D-015 | 2026-09-24 | 要件・技術方針・WBSは公開、競合分析・差別化・ストア戦略は非公開（`docs/private/`） | 開発の経緯は公開して残したいが、競合分析と戦略は外に出さない |
| D-016 | 2026-09-24 | 名前を分離する。リポジトリ・ローカルフォルダは `health-connect-viewer`、表示名は「Health Connect Viewer」（仮）、Android packageは `com.yskms.healthconnectviewer` | 既存アプリ（`com.yskms.filto`）の命名規則に合わせる。packageはPlayで公開すると変更できないため最初に確定し、表示名は後から変えられるので仮のままにする |
| D-017 | 2026-09-25 | Viewerは既存アプリとは独立したKotlin / Composeプロジェクトとして実装する。既存アプリ（Expo / React Native）の実装コードの直接移植は前提とせず、Viewerに適用できる検証知見とテスト観点のみを参照する（[lessons.md](lessons.md)）。現時点では共通パッケージを作成しない | 技術スタック・Health Connectの利用方向（書き込みと読み取り）・データモデルが異なり、流用できるコードはアプリの中心部分ではない。D-003は維持する（一度Expoへの変更を検討したが、外部レビューを経て撤回） |
| D-018 | 2026-09-25 | スクリーンショットと画面録画は既定で禁止しない。Recent Appsのプレビュー保護や任意のスクリーンショット防止は、必要性を確認して将来検討する | 健康グラフを利用者自身が保存・共有する用途が想定されるため。共有機能をMVPに入れることとは別の判断 |
